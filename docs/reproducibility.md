# Research scope and reproducibility

This project presents **34 small-model ablation exports with 10.69M–54.74M parameters**, experimental implementations, and a common CPU evaluation. Its findings concern the recorded models and test protocol. They do not establish faithful reproduction of the cited papers, controlled comparisons between every run, or production readiness.

## Evaluation protocol

The **October 6, 2026 evaluation** covers all 34 FP32 exports at Hugging Face revision `65951289352c1a036b12ba6d888af037e7c90b13`. It uses an Intel Core i7-8750H, Windows 11, PyTorch 2.6.0+cu124, one CPU thread, batch size 1, and FP32 parameters. The [environment](../experiments/evaluation/model-audit-2026-10-06/environment.json), [exact corpus](../experiments/evaluation/model-audit-2026-10-06/corpus.json), and [per-run results](../experiments/evaluation/README.md) are recorded separately from the model files.

The corpus contains the first **32 non-heading WikiText-2 raw test paragraphs** with at least 260 UTF-8 bytes, each truncated to 260 bytes at a complete character boundary. It is a small diagnostic sample. Training/test overlap has not been exhaustively checked; these scores are not full WikiText benchmark results.

Byte models predict the next four-byte patch with teacher forcing. NLL is measured in nats per byte; bits/byte is NLL divided by `ln(2)`, and byte perplexity is `exp(NLL)`. BPE models map Qwen token IDs outside their saved vocabulary cap to 0. Their perplexity describes that lossy token stream and cannot be directly compared with byte perplexity. The original evaluation did not record the resolved Qwen tokenizer revision, limiting exact BPE reproduction.

All shared measurements use **phase 1 with deletion disabled**. They do not establish phase-2 compression quality or speedups. See the [full model card](model_cards/cpu1-ablations-final.md#evaluation-methodology) for scoring, timing, generation, and correctness-probe details.

## Recorded outcomes

| Check | Outcome | Meaning |
|---|---|---|
| Strict checkpoint loading | 34/34 | State dictionaries match the recorded constructors |
| Finite loss | 30/34 | Four exports produce nonfinite loss |
| Prefix causality | 16 PASS, 14 FAIL, 4 ERROR | Failed models can use future information; ERROR is not a pass |
| Recurrent chunk equivalence | 26 FAIL; 8 Transformer N/A | The recurrent implementation disagrees between full and chunked execution |

A low loss from a model that fails causality is not evidence of valid autoregressive prediction quality. A causality pass does not resolve a recurrent chunk failure. Differences in model size, saved step, training signal, and configuration prevent interpreting successive run numbers as a controlled one-component ablation.

The [October 10 checkpoint validation](../experiments/evaluation/readme-validation-2026-10-10.json) records matching hashes, strict loading, losses within `1e-6`, and matching causal/chunk outcomes for all 34 exports. The complete timing and continuation tables retain their original October 6 measurements. Single-step forward timing and generated bytes/second measure different work; neither is a hardware-independent performance guarantee.

## Architecture and dataset evidence

For the ablation family, the [architecture inventory](../experiments/evaluation/architecture-review-2026-10-10.json) covers **128 constructions**: 34 published configurations in both ablation backends and 30 current presets in each backend. Meta-tensor inventories establish parameter counts and module structure. Small random-weight CPU probes exercise code paths; they do not establish trained quality or full-scale GPU behavior. The [architecture guide](architecture-review.md#run-by-run-explanations) explains each run family, the scan defect, boundary causality, and gate behavior.

The [dataset inventory and card](model_cards/cpu1-ablation-dataset.md) describe 917 Parquet shards. Direct inspection covers **three fixed shards**, plus synthetic tokenizer/reader cases. It found teacher-reader alignment, mask-format, and UTF-8 limitations. The service-reported 46,029 rows were checked on October 10; this is not an independent scan of every row. The 1,346-file training archive is inventoried separately; not every intermediate binary has been loaded or numerically evaluated.

Native C/C++ benchmarks use synthetic weights and fixed-formula byte feedback. They are kernel experiments, not measured useful text generation from these trained checkpoints. Compilation, checkpoint loading, and native/PyTorch numerical parity remain unvalidated in the recorded environment.

## Repeating and extending the experiments

Use the [setup and usage guide](usage.md) to install dependencies, load one pinned export, and run CPU scoring or generation examples. Use the [manifest and configurations](../experiments/README.md) to identify a model, and [platform recipes](provenance/README.md) to prepare a new run. Model hashes identify files; saved steps and configured token budgets do not prove convergence or completed training exposure.

Exact retraining remains limited by missing per-job source, dependency, teacher/tokenizer, extraction, document-list, and projection records. The requirements provide minimum versions rather than a complete lockfile. Fresh CUDA/ROCm training and end-to-end resume have not been validated by the CPU evaluation.

Model and dataset licenses are declared in their cards. The source tree currently has no project license file. The saved WikiText sample retains its [upstream attribution and terms](../experiments/evaluation/model-audit-2026-10-06/CORPUS_LICENSE.txt).
